### SEC-03: Unescaped User Input in HTML Messages (Entity Parsing Denial of Service)
- **Severity:** **MEDIUM**
- **Affected Location:** [`telegram_bot_shajare.py`](file:///c:/Users/PC%20Ishragh/Desktop/shajare1_bot/telegram_bot_shajare.py#L311-L338) (Lines 311–314, 333–338)
- **Evidence:**
  ```python
  # Line 311-314
  await update.message.reply_text(
      f"🔍 در حال جستجو برای: «<b>{user_text.strip()}</b>»...",
      parse_mode=ParseMode.HTML
  )

  # Line 333-338
  await update.message.reply_text(
      f"❌ متاسفانه اثری مطابق با «<b>{user_text.strip()}</b>» یافت نشد.\nمیتوانید کلمه دیگری را جستجو کنید.",
      reply_markup=no_res_keyboard,
      parse_mode=ParseMode.HTML
  )
  ```
- **Potential Impact & Exploitability:**
  When `parse_mode=ParseMode.HTML` is specified, Telegram expects valid XML/HTML entities. If a user enters `<test>`, `a & b`, or unclosed tags like `<b`, Telegram's API rejects the call with:
  `telegram.error.BadRequest: Can't parse entities: tag '...' is not closed`
  Because this exception is not caught, the search handler crashes, causing a persistent Denial of Service (DoS) for any query containing `<`, `>`, or `&`.
- **Recommended Remediation:**
  Import Python's built-in `html` library and escape the raw user text:
  ```python
  import html

  escaped_query = html.escape(user_text.strip())
  await update.message.reply_text(
      f"🔍 در حال جستجو برای: «<b>{escaped_query}</b>»...",
      parse_mode=ParseMode.HTML
  )
  ```
- **Verification Steps:**
  Send `<hello>` or `شجره & همایون` in search mode. The bot will escape the characters (`&lt;hello&gt;`) and process the search without raising API errors.

### SEC-04: Missing Per-User Rate Limiting & Concurrency Controls
- **Severity:** **MEDIUM**
- **Affected Location:** [`telegram_bot_shajare.py`](file:///c:/Users/PC%20Ishragh/Desktop/shajare1_bot/telegram_bot_shajare.py#L253-L285) (Lines 253–285)
- **Evidence:**
  When a user taps a level button (such as `level1` containing 60 tracks), the bot enters a sequential forwarding loop:
  ```python
  for i, p in enumerate(level_posts):
      await send_post(query.message.chat_id, p, context)
      if (i + 1) % 20 == 0:
          await asyncio.sleep(3)
      else:
          await asyncio.sleep(1.0)
  ```
- **Potential Impact & Exploitability:**
  There is no concurrency lock or cooldown per user. A malicious or impatient user can spam the `level1` or `level2` inline buttons 10 times consecutively. This spawns 10 parallel asynchronous forwarding tasks to the same chat, sending hundreds of requests, saturating the bot's event loop, and exhausting Telegram's global bot rate limit for all other users.
- **Recommended Remediation:**
  Add a state lock in `context.user_data`:
  ```python
  if context.user_data.get('is_forwarding'):
      await query.answer("لطفاً تا پایان ارسال قطعات قبلی صبور باشید.", show_alert=True)
      return

  context.user_data['is_forwarding'] = True
  try:
      # execute forwarding loop
  finally:
      context.user_data['is_forwarding'] = False
  ```
- **Verification Steps:**
  Trigger multiple rapid button presses; verify that subsequent presses are throttled and answered with an alert instead of launching parallel dispatch loops.
